# Authorization Implementation Plan

## Contract and Dependencies

Implement trusted storage-side [row/cell semantics](../../specs/authorization.md) for SQL and direct IPC alike. Depend on [identity/context](../ddl-identity/README.md), [permission definitions](../ddl-permissions/README.md), [catalog](../data-dictionary/README.md) and [transaction validation](../concurrency-mvcc/README.md). Definition parsing belongs to permission DDL; runtime evaluation and sanitized access belong here.

## Decisions Before Implementation

Fix bounded typed policy IR, trusted context inputs, runtime error/null behavior and dependency tracking. Effective authority intersects caller permissions with invocation scope; ownership is administrative authority, not query access. Unsupported external policy inputs remain rejected until version pinning/revalidation exists. Define expression evaluation/error ordering consistently with SQL, optimizer and storage pushdown.

## Increments

| ID | Observable test first | Minimum implementation and evidence |
| --- | --- | --- |
| AU-1 | Table-driven reference cases deny missing grants/ALLOW policies and combine ALLOW alternatives with every RESTRICT | Bounded trusted evaluator over pinned user/role/context; true alone allows, null/errors never allow; no owner/admin bypass |
| AU-2 | Two authenticated users see different rows/cells; denied variable-length values leave no bytes or lengths | Select MVCC/private version first, enforce row visibility then per-cell checks, and emit VALUE/NULL/REDACTED into sanitized IPC buffers |
| AU-3 | Hidden-value predicates, index probes and redacted required inputs cannot influence managed results improperly | Validate restricted expressions/access paths after authorization; compare optimized/batched access with independent per-cell/reference scans |
| AU-4 | Patching a readable/writable cell preserves hidden unchanged fields and checks old/new policy pairs | Storage builds full rows; one applicable ALLOW must pass both update checks, changed fields need read plus write rights, policy-driving fields remain immutable |
| AU-5 | Insert defaults/implicit nulls require grants/cell policies except generated identities; delete needs explicit row-delete rights | Apply defaults then creation policy/constraints, independently authorize later reads and prevent scope widening through self-modification |
| AU-6 | Policy/membership/token/schema changes race commit and abort stale writes while admitted reads retain bounded snapshots | Record authoritative dependency epochs/base versions and revalidate under serialized publication; no external inputs without a contract |
| AU-7 | Bypassing SDK, forging row handles or losing cache invalidation cannot widen access | Real hostile IPC clients in sandbox, complete cache validity domains and sanitized non-disclosing diagnostics |

## Acceptance and Handoff

Use real control-created users/policies rather than hard-coded production fixtures. Compare byte output and engine-managed errors across hidden-data variations, with constraint/conflict outcomes and timing inference documented as limits. Already delivered values cannot be revoked; immediate read revocation remains deferred. First behavior: an independent policy-composition truth table including no-ALLOW, null, restrict and update-pairing denial.

## Progress

- **AU-1: in progress.** The storage module has a bounded typed evaluator, transitive role closure (4096-edge bound, cycle/duplicate rejection), principal/role matching, separate grant and invocation-scope checks, deny-by-default ALLOW/RESTRICT composition, SQL NULL behavior, and same-policy old/new UPDATE pairing. Catalog loaders now derive grants, roles, schema, and row/cell policies from the pinned snapshot and bind policy expressions to declared dependencies. Token-authenticated invocation admission and the initial ADMIN gateway path are covered. Remaining work is complete semantic validation across every DDL route and wider SQL/policy expression acceptance.
- **AU-2: in progress.** Catalog-derived read paths choose the private/pinned row before decoding, require schema USAGE and relevant column authority, apply row policy before cell checks, and return VALUE/NULL/REDACTED cells. The token-authenticated cell-view acceptance creates users, tokens, schema, table, grants, and policies through ADMIN, then scans two different-sized secrets through executor IPC: one reader sees values, the other receives identical REDACTED cells. Confined direct executor tests bypass the SDK and verify forged relation and row handles fail with durable aborts and no result. Handle scope/expiration, hidden-versus-absent relation diagnostics, and the absence of cross-invocation decision caching are covered. Remaining work includes broader hostile IPC sequences and diagnostic comparisons for mutation/constraint outcomes.
- **AU-4: in progress.** Catalog-backed executor UPDATE loads the pinned schema, grants, role closure, and policies; storage checks row visibility and UPDATE plus SELECT/UPDATE permissions for every changed cell against old and proposed rows. It preserves hidden unchanged cells, rejects policy-driving-field writes, and revalidates dependencies at commit. Real-redb and confined SQL DML tests cover the initial path. Broader SQL predicate and policy combinations remain open.
- **AU-5: in progress.** Catalog-backed executor INSERT materializes defaults, allocates generated UUID identity, evaluates row/cell INSERT policies and CHECK constraints, and validates index constraints before publication. DELETE requires visible-row access and explicit table DELETE authority without requiring readability of every field. Real-redb and confined DML tests cover initial behavior. Broader SQL DEFAULT/column-list forms and the full constraint/identity edge-case matrix remain open.
- **AU-6: in progress.** Catalog-backed read/write paths capture schema, role, grant, policy, expression, and identity dependencies from the pinned snapshot and include them in final commit guards; token, grant, role-membership, and identity-change regressions cover stale-write abort or serialization. Lower-level trusted projection APIs still accept caller-supplied dependencies, and the complete cross-DDL race matrix remains open.
- **AU-3: implemented slice.** `InvocationTransaction::probe_catalog_unique_index` supports restricted unique equality after pinned schema/index validation, refuses hidden or conditionally readable key cells before inspecting the requested key, reconciles snapshot candidates with staged values/deletes, and returns only authorized sanitized rows. The optimizer selects validated unique point and authorized leading-key range hints, and the SDK independently validates and reauthorizes them before execution, falling back to the reference scan when unavailable or oversized. Storage regressions compare point/range results with authorized reference scans; hidden-key point and range cases return uniform fallback/unavailable results. Broader data/workload equivalence and complex-predicate redaction-error equivalence remain open.
- **AU-7: partial.** Confined SDK-bypass tests reject forged relation handles for OPEN SCAN and STAGE INSERT, and forged row handles for both STAGE UPDATE and STAGE DELETE; capability lifetime tests cover connection/invocation scope and invalidation after relation close or mutation, and exact IPC bytes match for hidden versus absent relations. Real-redb staging regressions verify hidden-row and absent-row UPDATE and DELETE attempts return the same `NotFound` diagnostic, and CHECK failures on distinct rows/values return identical diagnostics. Broader hostile IPC sequences and global unique/FK constraint inference remain open.
