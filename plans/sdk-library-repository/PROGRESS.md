# SDK Library Repository Progress

## SLR-1: Repository record and storage — verified slice

- Contract: [SDK library repository](../../specs/sdk-library-repository.md). Instance-local repositories load validated immutable releases, atomically publish installs, discard incomplete `.install-*` directories on startup, list releases in stable order, and remove a release only after all SDK pins drain.
- Implementation: extended `SdkReleaseRegistry` with repository open/install/list/remove operations and the repository-facing `SdkLibraryRepository` alias. Install checks bounded canonical metadata, instance target/profile, dependency allowlist, digest and ELF SONAME/dependencies/RPATH/RUNPATH; it writes synchronized read-only files in a temporary directory and publishes with `renameat2(RENAME_NOREPLACE)`. Repository quota counts installed release bytes without automatic eviction. Resolve pins share the same lock used by release removal.
- Regression: repository tests cover reopen persistence, incomplete staging cleanup, idempotent install, release identity conflict, profile/dependency/digest rejection, resolve pins blocking removal, and successful removal after release. Existing legacy registry cases still pass during migration.
- Verification: `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test sdk_registry --locked` passed (7 tests); `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --test sdk_registry --locked -- -D warnings`, `nix develop --no-update-lock-file -c cargo fmt --all -- --check`, and `git diff --check` passed. Nix 2.34.9 rejects the repository's documented `nix develop --locked` spelling; the equivalent `--no-update-lock-file` mode was used. The full delegated-cgroup workspace suite has not been run for this increment.
- Remaining: service startup still uses deployment release directories and a content cache. Authenticated list/install/remove operations, query-only protocol, client configuration, client command migration, and end-to-end repository-only loading are not implemented yet.
- Next increment: expose typed authenticated list/install/remove operations over the control API, with list available to authenticated users and mutation restricted to current database administrators.

## SLR-2: Authenticated repository API — implementation in progress

- Implemented slice: the supervisor opens an instance-local `sdk-libraries` repository by default (overridable with `--sdk-repository-dir`, quota with `--sdk-repository-max-bytes`) and attaches it to the trusted staging/control service. The typed ADMIN request `sdk_libraries.list` accepts no unrecognized arguments. Its server response includes installed release compatibility metadata only; it returns no paths or binary bytes. `AdminClient::list_sdk_libraries` decodes the response strictly into typed release records.
- Authorization boundary: the list branch is reached only through an authenticated ADMIN session and uses the repository handle held by `StagingStore`; query workers do not receive the handle. A fresh-snapshot `StorageManager::is_database_admin` check is available for the mutation handlers that remain to be implemented.
- Mutation slice: `sdk_libraries.remove` rechecks current database-admin authority and removes every ABI for the release, subject to live pins. `sdk_libraries.install` streams metadata and SDK bytes through bounded kind-19 chunks, checks owner and contiguous offset, and validates/publishes only after the full transfer. Install/remove accept client-generated operation IDs; successful results are persisted outside the release directory, replayed on retry, and available through owner-scoped `sdk_libraries.operation_status`.
- Authorization/integration evidence: the real gateway dispatch integration exercises ordinary-principal listing and denied removal, administrator streamed install, status lookup, and repeated removal with the same operation ID. The session request-ID allowlist and public frame codec now accept the upload chunk kind while preserving control-mode and current-admin checks.
- Focused verification passed: `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test client_admin --test sdk_registry --locked` (47 client admin tests and 8 repository tests); `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test commit storage_manager_runtime_and_metadata_reads_enforce_authorization --locked`; `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --all-targets --locked -- -D warnings`; `nix develop --no-update-lock-file -c cargo fmt --all -- --check`; and `git diff --check`.
- Remaining SLR-2 work: test authorization revocation during an upload, conflicting same-ID and same-release installs, expired/stale pagination against populated repositories, recovery/status after process restart and a lost finish reply, durable failed-operation outcomes, and executor IPC non-reachability. Repository CLI commands are part of SLR-5. No full delegated-cgroup workspace run has been performed yet.
- Next increment: complete the SLR-2 failure/recovery tests and close remaining operation outcome edge cases, then move to query-only submission profile negotiation (SLR-3).

## SLR-3: Query-only submission profile — verified slice

- Contract: [client protocol](../../specs/client-protocol.md). Query clients can request `sdk_library_mode: repository` in HELLO; the server must echo it. A repository-profile PREPARE repeats the profile and omits SQL-library length/digest. The profile must match the authenticated connection's HELLO; old peers, mismatches, legacy SDK chunks, and unexpected SDK fields fail closed.
- Client/server changes: added repository-profile constructors for one-shot and interactive-v2 clients. They do not retry the legacy profile when HELLO does not echo the capability. The query client sends only artifact and parameters, expects no SDK chunk limit, and skips kind-12 uploads. Server session state carries the negotiated profile and rejects the old SDK chunk path for that connection. Legacy clients retain the old path until SLR-7 retirement.
- Regression evidence: protocol tests cover HELLO capability parsing, query-only PREPARE shape and rejection of mixed profile/library fields; the client package integration drives both legacy upload and repository-profile submission, checking that the repository flow sends only query and parameter chunks before SEAL; another client test proves an old peer's missing HELLO echo is rejected before AUTH; the connection-session integration verifies the server returns a query-only prepare shape and rejects a legacy SQL-library chunk.
- Verification passed: `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test client_protocol --locked`; `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test client_admin repository_profile_does_not_fall_back_when_peer_omits_capability --locked`; `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test client_package packager_compiles_and_atomically_publishes_metadata_without_loading_query --locked`; `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test commit storage_manager_runtime_and_metadata_reads_enforce_authorization --locked`; `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --all-targets --locked -- -D warnings`; and `nix develop --no-update-lock-file -c cargo fmt --all -- --check`.
- Remaining: SLR-4 executor staging still needs confined process acceptance and pin-release coverage for launch failure, cancellation, timeout, and worker exit. SLR-6 must make interactive SQL, run-sql, and package submit select this profile from persistent client config and remove the SDK DLL from package layout. Full delegated-cgroup workspace acceptance remains outstanding.
- Next increment: continue SLR-4 with confined executor staging and cleanup-path acceptance.

## SLR-4: Supervisor resolve, pin, and stage — verified slice

- Contract: [SDK library repository](../../specs/sdk-library-repository.md). `start_with` resolves the exact PMF1 release through the configured validator before admission; a failed resolution discards prepared work without calling admission. A successful `SealedSubmission` retains the resolved `SdkLibraryPin`. Executor preparation copies the pinned library beside `query.so` under its validated SONAME, read/execute-only, and holds the pin in the private artifact-directory owner through cleanup. The trusted supervisor performs data-only resolution and never loads the library.
- Regression evidence: `repository_sdk_pin_is_held_from_admission_until_finish` installs a real release and proves resolver pin lifetime around START. The delegated-cgroup `sandboxed_repository_sdk_library_loads_and_stays_pinned_until_worker_cleanup` installs the library into an instance repository, resolves and stages it from the repository, runs query and SDK constructors only in the confined executor, verifies removal is denied while pinned, and removes the release after worker cleanup. The `supervisor_and_gateway_binaries_commit_a_confined_submission` process test now installs an SDK into the instance repository, negotiates the query-only profile through TCP, and commits a query linked to that repository release through the supervisor and confined executor. `sdk_resolution_failure_discards_prepared_work_before_admission_callback` covers pre-admission failure; repository tests cover digest/profile/dependency rejection and concurrent immutable resolution.
- Verification passed: `nix develop --no-update-lock-file -c make -f engine/sdk/Makefile release-profile` validated 10 engine binaries and one query fixture; both repository-backed confined tests passed inside delegated `systemd --user` units with writable `cpu`, `memory`, and `pids` controllers. The full delegated-cgroup workspace suite has not been run.
- Remaining: exercise repository pin cleanup on launch failure, cancellation, and timeout, in addition to the verified normal worker exit. The full delegated-cgroup workspace suite remains outstanding.
- Next increment: add confined cleanup-path tests and proceed through the remaining client/retirement gates.

## SLR-5: Persistent client configuration and repository commands — verified slice

- Contract: [SDK library repository](../../specs/sdk-library-repository.md). Added strict `PRDB-CLIENT-CONFIG-1` UTF-8 JSON parsing and encoding for default instance, per-instance endpoint, SDK release/profile/ABI, default credential, named credentials, and local tool paths. Config reads reject duplicate/unknown fields, unsupported formats, malformed/canonical-value violations, oversized files, symlinks, non-owner files, and broad file/directory permissions. Updates write mode-0600 temporary files, sync, rename atomically, and sync the private mode-0700 parent. Config and credential buffers are zeroized on drop/after parsing where practical; debug output redacts token secrets.
- CLI changes: `prdb-client instance list|show|set` manages endpoints, credentials and named profiles; updating an instance preserves its SDK selection unless all SDK selection fields are explicitly supplied. `prdb-client sdk-library list|select|install|remove` uses the typed authenticated API, default configured credential and per-instance endpoint. `select` checks the remote release and ABI, then verifies the local SDK release path, ABI directory and shared-library SHA-256 before atomically saving the selection. Relative local SDK paths resolve from the config file directory.
- Regression evidence: config tests cover duplicate keys, unknown fields, malformed/noncanonical values, 1 MiB bound, private atomic create/read, symlink and broad permission rejection, credential base64url round-trip, default instance lookup, and credential redaction behavior. CLI tests cover endpoint/credential update while preserving SDK selection, named credential profiles, and exact local release profile/ABI/digest matching. Configured `sdk-library list` and `select` run through mock control gateways using saved credentials; configured `install` streams metadata and library bytes, checks typed finish/list responses, and configured `remove` sends a typed release operation. The earlier real gateway integration covers ordinary-user listing, admin-only mutation, revocation, and operation outcomes.

## SLR-6: Package and SQL client migration — implementation slice

- Package behavior: `package_query_repository` links against the selected local SDK but publishes only `query.so`, PMF1, PSC1, and the query digest. `prdb-packager` now uses this layout by default; `--legacy-package` temporarily retains the old SQL DLL layout for compatibility. Configured query-only clients reject package `sql.so` or `sql-library.sha256` files before connecting.
- Client behavior: `submit` and `run-sql` accept configured `--instance`/`--config` settings, resolve and verify endpoint overrides, select a default or named credential profile, and require query-only repository negotiation without downgrade. `submit` checks PMF release, ABI, CPU and runtime profile against the selected instance before upload. `run-sql` uses saved local SDK/compiler paths and settings to compile a query-only package. `interactive-sql` has a config path, builds in-memory zeroizing RUNAS credential profiles, uses the selected ABI 3 SDK build, and negotiates repository mode on interactive v2 connections and transaction recovery requests.
- Regression evidence: the package integration test verifies default packager output has no SDK DLL or DLL digest sidecar. It launches configured `prdb-client submit` and `run-sql` against mock gateways, verifies saved credentials, repository HELLO/PREPARE, query-only artifact/parameter chunks, selected ABI/release in the generated manifest, and durable start receipts. It also runs configured interactive SQL through repository-profile HELLO/AUTH and real v2 BEGIN/COMMIT frames. While the transaction is active, a separate `instance set` process is rejected by the shared selection lock; the same change succeeds after COMMIT. CLI tests cover manifest mismatch and legacy SDK file rejection. Credential profile tests cover in-memory named profile loading and authentication material. Client-config lock tests cover lock exclusion and private creation of a missing config parent.
- Verification passed: `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test client_package --locked` (10 tests); `nix develop --no-update-lock-file -c cargo test -p prdb-engine --bin prdb-client --locked` (23 tests); `nix develop --no-update-lock-file -c cargo test -p prdb-engine --lib client_config::tests --locked` (5 tests); `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --all-targets --locked -- -D warnings`; and `nix develop --no-update-lock-file -c cargo fmt --all -- --check`. The delegated cgroup probe passed with writable `cpu`, `memory`, and `pids` controllers; the full delegated-cgroup workspace suite has not been run.
- Remaining: interactive recovery/RUNAS and autocommit selection behavior; full repository admin CLI integration; confined repository-library executor acceptance and all pin cleanup paths. SLR-7 must retire legacy package upload and `prdb-packager --legacy-package` compatibility.
- Next increment: complete configured admin CLI boundary tests and repository-backed confined executor acceptance before SLR-7 retirement.

## SLR-7: Compatibility retirement — in progress

- Repository startup now builds an instance compatibility profile from CPU/runtime only; manifest SDK release numbers are resolved exactly by the configured repository, so installing a second release does not require a supervisor restart or another release flag. Supervisor startup no longer accepts `--sdk-release`, release directories, cache paths/limits, or the legacy static-library fallback flag. Its default and only SDK resolver is the instance-local repository.
- Regression evidence: a manifest test proves a repository profile accepts release 7 while a fixed release-1 profile rejects it. Supervisor CLI tests check that retired options are absent from help and rejected during argument parsing. The process-level supervisor test installs a release under the managed instance directory, starts without release/cache flags, negotiates repository mode, and commits through a real confined worker. Bootstrap now recognizes only the mode-0700 `sdk-libraries` service directory as an allowed addition to managed instance state.
- Verification passed: `nix develop --no-update-lock-file -c cargo check -p prdb-engine --all-targets --locked`; the repository-profile multi-release unit test; the supervisor retired-option CLI test; the process-level supervisor/gateway confined test inside delegated `systemd --user`; `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --all-targets --locked -- -D warnings`; and `nix develop --no-update-lock-file -c cargo fmt --all -- --check`.
- Remaining: remove SQL-library fields/chunks and client upload APIs, remove `--legacy-package` and legacy package layout, remove cache-only registry behavior, update process fixtures and deployment docs, then run complete delegated-cgroup end-to-end acceptance.
- Next increment: retire the packager's legacy package mode and the client SQL-library upload APIs while keeping server PREPARE and staging payloads query-only.
