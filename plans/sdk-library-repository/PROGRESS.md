# SDK Library Repository Progress

## SLR-1: Repository record and storage — verified slice

- Contract: [SDK library repository](../../specs/sdk-library-repository.md). Instance-local repositories load validated immutable releases, atomically publish installs, discard incomplete `.install-*` directories on startup, list releases in stable order, and remove a release only after all SDK pins drain.
- Implementation: extended `SdkReleaseRegistry` with repository open/install/list/remove operations and the repository-facing `SdkLibraryRepository` alias. Install checks bounded canonical metadata, instance target/profile, dependency allowlist, digest and ELF SONAME/dependencies/RPATH/RUNPATH; it writes synchronized read-only files in a temporary directory and publishes with `renameat2(RENAME_NOREPLACE)`. Repository quota counts installed release bytes without automatic eviction. Resolve pins share the same lock used by release removal.
- Regression: repository tests cover reopen persistence, incomplete staging cleanup, idempotent install, release identity conflict, profile/dependency/digest rejection, resolve pins blocking removal, and successful removal after release. Existing legacy registry cases still pass during migration.
- Verification: `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test sdk_registry --locked` passed (7 tests); `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --test sdk_registry --locked -- -D warnings`, `nix develop --no-update-lock-file -c cargo fmt --all -- --check`, and `git diff --check` passed. Nix 2.34.9 rejects the repository's documented `nix develop --locked` spelling; the equivalent `--no-update-lock-file` mode was used. The full delegated-cgroup workspace suite has not been run for this increment.
- Remaining: service startup still uses deployment release directories and a content cache. Authenticated list/install/remove operations, query-only protocol, client configuration, client command migration, and end-to-end repository-only loading are not implemented yet.
- Next increment: expose typed authenticated list/install/remove operations over the control API, with list available to authenticated users and mutation restricted to current database administrators.

## SLR-2: Authenticated repository API — implementation in progress

- Implemented slice: the supervisor opens an instance-local `sdk-libraries` repository by default (overridable with `--sdk-repository-dir`, quota with `--sdk-repository-max-bytes`) and attaches it to the trusted staging/control service. The typed ADMIN request `sdk_libraries.list` accepts no unrecognized arguments. Its server response includes installed release compatibility metadata only; it returns no paths or binary bytes. `AdminClient::list_sdk_libraries` decodes the response strictly into typed release records.
- Authorization boundary: the list branch is reached only through an authenticated ADMIN session and uses the repository handle held by `StagingStore`; query workers do not receive the handle. A fresh-snapshot `StorageManager::is_database_admin` check is available for the mutation handlers that remain to be implemented.
- Mutation slice: `sdk_libraries.remove` rechecks current database-admin authority and removes every ABI for the release, subject to live pins. `sdk_libraries.install` streams metadata and SDK bytes through bounded kind-19 chunks, checks owner and contiguous offset, and validates/publishes only after the full transfer. Install/remove accept client-generated operation IDs; successful results are persisted outside the release directory, replayed on retry, and available through owner-scoped `sdk_libraries.operation_status`.
- Authorization/integration evidence: the real gateway dispatch integration exercises ordinary-principal listing and denied removal, administrator streamed install, status lookup, and repeated removal with the same operation ID. The session request-ID allowlist and public frame codec now accept the upload chunk kind while preserving control-mode and current-admin checks.
- Focused verification passed: `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test client_admin --test sdk_registry --locked` (47 client admin tests and 8 repository tests); `nix develop --no-update-lock-file -c cargo test -p prdb-engine --test commit storage_manager_runtime_and_metadata_reads_enforce_authorization --locked`; `nix develop --no-update-lock-file -c cargo clippy -p prdb-engine --all-targets --locked -- -D warnings`; `nix develop --no-update-lock-file -c cargo fmt --all -- --check`; and `git diff --check`.
- Remaining SLR-2 work: test authorization revocation during an upload, conflicting same-ID and same-release installs, expired/stale pagination against populated repositories, recovery/status after process restart and a lost finish reply, durable failed-operation outcomes, and executor IPC non-reachability. Repository CLI commands are part of SLR-5. No full delegated-cgroup workspace run has been performed yet.
- Next increment: complete the SLR-2 failure/recovery tests and close remaining operation outcome edge cases, then move to query-only submission profile negotiation (SLR-3).
